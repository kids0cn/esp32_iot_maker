## 1. 项目定位

| 项 | 内容 |
|----|------|
| **性质** | 中学生创客项目（教学 + 演示，非量产产品） |
| **做给谁** | 中学生（创客教学用）；同时作为可展示、可讲解的作品 |
| **核心命题** | 用 ESP32 把「环境感知 → 自动决策 → 执行动作」闭环跑通，并配一套离网供电演示 |
| **成功的样子** | 现场通电即可演示：空气变差 → 风扇自动换气 → 空气恢复 → 自动停止；外加一个能手动干预的网页 |

**关键约束：逻辑要真、外观可凑。** 这是教学演示装置，重点在传感判据、联动控制和供电概念都真实成立，不要求工业级外壳与可靠性。

## 2. 功能需求

优先级：**P0** = 核心演示必须跑通；**P1** = 规划中，一期后可加。

### F-01 自动换气（PM2.5 联动风扇）`P0`

| 项 | 内容 |
|----|------|
| **描述** | ESP32 周期性采集 PM2.5 传感器数据，超过阈值时启动风扇换气，回落到安全范围后停止 |
| **涉及设备** | PM2.5 传感器、进风扇、排风扇 |
| **验收标准** | ① 传感器读数能在网页/串口正确显示<br>② 人为制造烟雾使 PM2.5 升高 → 进/排风扇自动启动<br>③ 空气恢复后风扇自动停止，无需人工干预 |
| **待定** | 阈值取值；单一阈值 or 双阈值回差（防止临界值反复启停）；采样周期 |

### F-02 手动控制 `P0`

| 项 | 内容 |
|----|------|
| **描述** | 网页上提供每个执行设备（进风扇、排风扇，后续含灯光、除湿机）的启停开关 |
| **验收标准** | ① 点击开关，对应设备立即响应<br>② 页面能反映设备**当前真实状态**（不是只反映按钮被点过） |

### F-03 AP 热点 + Web 控制台 `P0`

| 项 | 内容 |
|----|------|
| **描述** | ESP32 自身开 AP 热点，设备直连后用浏览器访问控制页面，**不依赖现场路由器或外网** |
| **验收标准** | ① 手机/电脑能搜到并以约定密码连上热点<br>② 浏览器访问约定地址能看到控制页面<br>③ 页面内含手动控制与自动模式切换 |

### F-04 光伏 + 电池供电 `P0`

| 项 | 内容 |
|----|------|
| **描述** | 整套系统由太阳能光伏板 + 电池及附属设备供电，模拟光伏发电与储能 |
| **验收标准** | ① 光照下光伏板给电池充电、系统正常运行<br>② 遮挡光伏板后系统靠电池继续运行<br>③ 能演示/讲解「发电—储能—用电」的闭环 |
| **待定** | 是否需要电量监测（电压/电流采样并显示在网页上）——**加分项，待确认** |

### F-05 光照联动照明 `P1` ✅ 代码已实现

| 项 | 内容 |
|----|------|
| **描述** | 加光照传感器，检测到环境变暗时自动亮灯 |
| **涉及设备** | 光照传感器（H-07）、灯光（继电器通道 2） |
| **验收标准** | 遮挡传感器 → 灯亮；恢复光照 → 灯灭 |
| **阈值** | 光照低于 `lightDark`（默认 50%）开灯，存 NVS 可在网页调 |

### F-06 湿度联动除湿 + 温度联动空调 `P1` ✅ 代码已实现

| 项 | 内容 |
|----|------|
| **描述** | 湿度超阈值 → 继电器模拟打开除湿机；**温度超阈值 → 继电器模拟打开空调** |
| **涉及设备** | 温湿度传感器 DHT11（H-08）、继电器通道 3（抽湿机）/ 通道 4（空调） |
| **验收标准** | 湿度升到阈值 → 通道 3 吸合；温度升到阈值 → 通道 4 吸合；回落则停止 |
| **阈值** | `humiOn` 默认 70%、`tempOn` 默认 28°C，均存 NVS 可在网页调 |

> 「温度联动空调」是原需求没写、实现时补上的 —— 4 路继电器买回来后通道 4 闲置，
> 配 DHT11 的温度读数正好用上。**这条需求是从实现反推补录的**（2026-09-28）。

### F-07 自动/手动模式切换 `P0` ✅ 已实现

| 项 | 内容 |
|----|------|
| **描述** | 两种模式可切换；自动模式下无需人工干预，手动模式下人工接管 |
| **已定** | 切换**不复位**设备状态；模式存 NVS，**断电后回默认（自动）**。语音执行完会**自动切到手动**，免得被自动逻辑改回去 |
| **已定** | 手动模式**无时限**，不自动回落到自动 —— 教学演示要能一直讲下去 |

### F-08 语音控制 4 路设备 `P0` ✅ 代码已实现

| 项 | 内容 |
|----|------|
| **描述** | 语音模块（CI1302）通过 UART2 发指令，控全部 4 路设备的开/关 |
| **涉及设备** | 语音模块（H-10）、继电器 4 通道 |
| **指令集** | 8 条：开灯 / 关灯 / 开风扇 / 关闭风扇 / 开抽湿机 / 关抽湿机 / 开空调 / 关空调 |
| **验收标准** | ① 说出指令 → 对应继电器动作<br>② 网页能看到模块在线状态与最近一条指令<br>③ 一条指令只执行一次，不重复触发 |
| **协议要点** | 上电**必须回握手帧** `A5 FA 00 80 0A 00 22 FB`，否则模块刷屏 + 波特率乱跳；第 6 字节是**厂商命令码不是校验和**，只能整帧逐字节比对（详见 `CLAUDE.md` 第 12 条） |

> ⚠️ **空调 / 抽湿机这 4 条命令词要重烧语音模块固件才生效** —— 模块里没有这几个词，
> 主程序收到了也不认。详见 [`项目状态.md`](项目状态.md) 第二节。

### 其他观察（不影响功能，供参考）

- **HTTP 解析较脆弱**（仅原版）—— 靠 `currentLine.endsWith("GET /ON")` 逐字符匹配，没有完整解析请求行。追过执行顺序，**实际能工作**（那 7 个字符攒齐的瞬间就命中），但扩展成多设备会不好改。v2 换 `WebServer` 库后此问题消失。
- **`delay(2000)` 决定响应节奏**（仅原版）—— 主循环 2 秒一轮，网页响应和自动判据更新都被拖慢。v2 改用 `millis()`。
- **GPIO 2 是 ESP32 的 strapping 引脚** —— 影响启动模式判定，接继电器有潜在上电风险。若后续遇到下载/启动异常，可换到 GPIO 25/26/27/32/33（改 `relayPin` 一个常量即可）。⚠️ **v2 已经重排过引脚，这串只对原版成立**，当前分配见 `文档/接线与引脚.md`。
- **WiFi 热点是开放网络**（热点名 `零碳智能家居`，**密码为空**）—— 演示时省掉输密码这一步。⚠️ 别用于真实场景；要改密码的话**必须 8 位以上**，1~7 位会让整个热点起不来（详见 `main.cpp` 里 `WIFI_PASS` 那段的注释）。
- **浓度公式未经标定** —— `(voltage - 0.6) * 166.67` 是社区常用近似式，输出是**相对值**而非精确 μg/m³。用于"高/低"判断足够，别当仪器读数用。
- **采样脉冲周期**（仅原版）—— 1288µs vs 手册 10ms，详见 [`v2改动说明.md`](v2改动说明.md)。v2 已修。

## 7. 整体验收

一期（P0）完成的判定标准 —— **现场能完整演示一遍**：

1. 通电，系统由光伏/电池供电启动
2. 手机连上 ESP32 热点，打开网页，看到传感器实时读数
3. 制造烟雾 → 网页上 PM2.5 数值升高 → 进/排风扇自动启动
4. 空气恢复 → 风扇自动停止
5. 在网页上手动开关风扇，设备立即响应
6. 切换到自动模式，重复第 3～4 步仍然成立
