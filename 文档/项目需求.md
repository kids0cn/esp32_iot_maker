# 项目需求

> 中学生物联网创客项目 —— ESP32 智能家居模拟系统
> 建立：2026-09-20 ｜ 状态：**需求采集阶段**（待现有代码与设备照片入库后细化）

本文件是项目的**需求正文**。README 是仓库门面，这里才是要做什么的清单。

---

## 1. 项目定位

| 项 | 内容 |
|----|------|
| **性质** | 中学生创客项目（教学 + 演示，非量产产品） |
| **做给谁** | 提供方的孩子；同时作为可展示、可讲解的作品 |
| **核心命题** | 用 ESP32 把「环境感知 → 自动决策 → 执行动作」闭环跑通，并配一套离网供电演示 |
| **成功的样子** | 现场通电即可演示：空气变差 → 风扇自动换气 → 空气恢复 → 自动停止；外加一个能手动干预的网页 |

**关键约束：逻辑要真、外观可凑。** 这是教学演示装置，重点在传感判据、联动控制和供电概念都真实成立，不要求工业级外壳与可靠性。

## 2. 功能需求

优先级：**P0** = 核心演示必须跑通；**P1** = 规划中，一期后可加。

### F-01 自动换气（PM2.5 联动风扇）`P0`

| 项 | 内容 |
|----|------|
| **描述** | ESP32 周期性采集 PM2.5 传感器数据，超过阈值时启动风扇换气，回落到安全范围后停止 |
| **涉及设备** | PM2.5 传感器、进风扇、排风扇 |
| **验收标准** | ① 传感器读数能在网页/串口正确显示<br>② 人为制造烟雾使 PM2.5 升高 → 进/排风扇自动启动<br>③ 空气恢复后风扇自动停止，无需人工干预 |
| **待定** | 阈值取值；单一阈值 or 双阈值回差（防止临界值反复启停）；采样周期 |

### F-02 手动控制 `P0`

| 项 | 内容 |
|----|------|
| **描述** | 网页上提供每个执行设备（进风扇、排风扇，后续含灯光、除湿机）的启停开关 |
| **验收标准** | ① 点击开关，对应设备立即响应<br>② 页面能反映设备**当前真实状态**（不是只反映按钮被点过） |

### F-03 AP 热点 + Web 控制台 `P0`

| 项 | 内容 |
|----|------|
| **描述** | ESP32 自身开 AP 热点，设备直连后用浏览器访问控制页面，**不依赖现场路由器或外网** |
| **验收标准** | ① 手机/电脑能搜到并以约定密码连上热点<br>② 浏览器访问约定地址能看到控制页面<br>③ 页面内含手动控制与自动模式切换 |

### F-04 光伏 + 电池供电 `P0`

| 项 | 内容 |
|----|------|
| **描述** | 整套系统由太阳能光伏板 + 电池及附属设备供电，模拟光伏发电与储能 |
| **验收标准** | ① 光照下光伏板给电池充电、系统正常运行<br>② 遮挡光伏板后系统靠电池继续运行<br>③ 能演示/讲解「发电—储能—用电」的闭环 |
| **待定** | 是否需要电量监测（电压/电流采样并显示在网页上）——**加分项，待确认** |

### F-05 光照联动照明 `P1`

| 项 | 内容 |
|----|------|
| **描述** | 加光照传感器，检测到环境变暗时自动亮灯 |
| **涉及设备** | 光照传感器、灯光（经继电器） |
| **验收标准** | 遮挡传感器 → 灯亮；恢复光照 → 灯灭 |

### F-06 湿度联动除湿 `P1`

| 项 | 内容 |
|----|------|
| **描述** | 加温湿度传感器，湿度超阈值时通过继电器模拟自动打开除湿机 |
| **涉及设备** | 温湿度传感器、继电器、除湿机（模拟负载） |
| **验收标准** | 湿度升高到阈值 → 继电器吸合、除湿机启动；湿度回落 → 停止 |

### F-07 自动/手动模式切换 `P0`

| 项 | 内容 |
|----|------|
| **描述** | 两种模式可切换；自动模式下无需人工干预，手动模式下人工接管 |
| **待定** | 切换时是否复位设备状态；手动模式是否有时限后自动回落到自动模式 |

## 5. 待确认问题

原计划的 7 个问题，2026-09-20 收到现有代码后**已全部有答案**：

| 问题 | 答案 | 依据 |
|------|------|------|
| 引脚分配 | 继电器 IN = **GPIO 2**；PM2.5 驱动 LED = **GPIO 13**；PM2.5 模拟输出 = **GPIO 34** | 代码 `// 引脚定义` |
| PM2.5 阈值策略 | **双阈值回差**：> 75 开风扇，< 50 关风扇，50～75 之间**保持原状态** | 代码 `loop()` 自动控制逻辑 |
| 传感器型号 | **GP2Y1014AU**（Sharp 兼容粉尘传感器），**模拟量输出**，5V 供电 | 商品页照片 |
| 风扇驱动 | 经 **5V 继电器模块（低电平触发）** 控 12V 风扇，**无 PWM 调速** | 代码 + 继电器照片 |
| 开发框架 | **Arduino**（ESP32 core），单 `.ino` 文件 | 代码结构 |
| Web 页面形态 | **固件内嵌字符串**，用 `client.println()` 逐行拼 HTML | 代码 `loop()` |
| 现有实现程度 | 见下方第 7 节「现有代码实现覆盖情况」 | 代码通读 |

**新发现的待确认问题**（收代码后才暴露出来的）：

- [ ] **进风扇 / 排风扇如何分别控制？** 现有代码只有 1 个 `relayPin`、1 路继电器，只能控一个设备。是再加一路继电器，还是两个风扇并联？
- [ ] **PM2.5 采样时序** —— 代码里 LED 脉冲总周期是 280+40+968 = **1288μs**，而 GP2Y1014AU 数据手册标称脉冲周期应为 **10ms**（常见 Arduino 例程此处是 `delayMicroseconds(9680)`）。疑为少写一位数字，**需实测核对**。
- [ ] **是否需要网页自动刷新？** 现有页面不刷新，PM2.5 数值只在点按钮后重新加载时才更新。
- [ ] **是否需要手动/自动模式切换开关？** 现有代码没有模式状态，手动操作会被下一轮自动逻辑覆盖。

### 其他观察（不影响功能，供参考）

- **HTTP 解析较脆弱**：靠 `currentLine.endsWith("GET /ON")` 字符串匹配，没有完整解析请求行。当前能工作，但扩展成多设备时会不好改。
- **`delay(2000)` 决定响应节奏**：主循环 2 秒一轮，所以网页响应和自动判据的更新周期都是 ~2 秒。
- **GPIO 2 是 ESP32 的 strapping 引脚**：影响启动模式判定，接继电器有潜在上电风险。若后续遇到下载/启动异常，可考虑换到 GPIO 25/26/27/32/33 这类普通引脚。
- **WiFi 密码 `12345678` 硬编码在源码里**：演示项目可接受，别用于真实场景。
- **浓度公式未经标定**：`(voltage - 0.6) * 166.67` 是社区常用近似式，输出是**相对值**而非精确 μg/m³。用于"高/低"判断足够，别当仪器读数用。

## 7. 整体验收

一期（P0）完成的判定标准 —— **现场能完整演示一遍**：

1. 通电，系统由光伏/电池供电启动
2. 手机连上 ESP32 热点，打开网页，看到传感器实时读数
3. 制造烟雾 → 网页上 PM2.5 数值升高 → 进/排风扇自动启动
4. 空气恢复 → 风扇自动停止
5. 在网页上手动开关风扇，设备立即响应
6. 切换到自动模式，重复第 3～4 步仍然成立
