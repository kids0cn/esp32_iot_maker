## 一句话

修掉一个**确证**的传感器时序 bug，补上**缺失的自动/手动模式切换**，把网页从「整页刷新」升级到「每秒自动更新」。

---

## 一、改了什么

### 1. 【修 bug】PM2.5 采样脉冲周期 968µs → 9680µs ★ 最重要

原版 `readPM25()` 三段延时是 `280 + 40 + 968 = 1288µs`。

**Sharp 数据手册实测规格**（GP2Y1010AU0F，与 GP2Y1014AU 同光学结构）：

| 参数 | 手册值 | 原版实际 | 偏差 |
|------|--------|---------|------|
| 脉冲周期 T | **10 ± 1 ms** | 1288 µs | **快 7.8 倍，超出规格** |
| 脉冲宽度 PW | 0.32 ± 0.02 ms | 320 µs | ✅ 正确 |
| 采样时点 | 脉冲后 0.28 ms | 280 µs | ✅ 正确 |

**为什么必须改**：脉宽对、周期错，意味着 LED 占空比从设计的 3.2% 变成 25%。手册 **Note 3** 明确写着「请遵循 LED 输入的推荐条件以保证可靠性」，另注「连续工作 5 年光衰 50%」。占空比拉高 8 倍会加速光衰、影响读数稳定性。

**改法**：`PM25_SLEEP_US = 9680`，并把这几个值提成命名常量、把手册依据写进注释。

**同时确认**：常见 Arduino 例程（[arduino-airquality](https://github.com/Trefex/arduino-airquality)）此处正是 `sleepTime = 9680` —— 原版是**漏写一位数字**，不是有意为之。

### 2. 【补功能】新增自动/手动模式切换（原 F-07）

**原版的问题**：`loop()` 每轮先跑自动判据、再处理网页请求，中间没有模式状态。手动点了「关闭风扇」，只要 PM2.5 > 75，**下一轮（约 2 秒后）就被自动开回来** —— 手动根本接管不了。

**v2 的做法**：
- 增加 `mode` 状态（`MODE_AUTO` / `MODE_MANUAL`），开机默认自动
- 自动模式下**风扇按钮置灰禁用**，并提示「切到手动后可自行操作」
- 手动模式下自动逻辑完全不介入

> 设计选择说明：没有做「一点手动按钮就自动切到手动模式」这种更"聪明"的行为。
> 显式切换语义更清楚，也正好能在演示时讲明白两种模式的区别 —— 这是教学项目。

### 3. 【换库】裸 `WiFiServer` → `WebServer` 库

原版手写 HTTP 应答头、靠 `endsWith("GET /ON")` 逐字符匹配路由。v2 用 ESP32 自带的 `WebServer`：

| 路由 | 作用 |
|------|------|
| `GET /` | 网页本体 |
| `GET /api/state` | 返回 JSON 状态（网页每秒来问一次） |
| `GET /fan/on` / `GET /fan/off` | 手动控制风扇 |
| `GET /mode/auto` / `GET /mode/manual` | 切换模式 |
| `GET /favicon.ico` | 回 204，免得串口刷 404 |

加设备（灯光、除湿机）就是多写两行 `server.on(...)`。

### 4. 【换写法】HTML 改用原始字符串

原版逐行 `client.println("...")`，引号要转义成 `\"`，没法缩进。v2 改用 C++ 原始字符串，HTML 怎么写就怎么贴。

### 5. 【补功能】AJAX 每秒刷新

新增 `/api/state` 返回 JSON，网页用 `fetch` 每秒拉一次，**数值自己跳，不再整页重新加载**。
顺带加了国标 PM2.5 分级配色（优/良/轻度/中度/重度/严重），数字和进度条按档变色。

### 6. 【去阻塞】去掉 `delay(2000)`

原版主循环固定 `delay(2000)`，网页响应被拖住。v2 改用 `millis()` 计时，采样周期 1 秒，`handleClient()` 随时能被调用。

## 二、刻意**没**改的地方

原则：**一次只动一个会影响传感器读数的变量**，否则出问题没法判断是哪个引起的。

| 保持原样 | 原因 |
|---------|------|
| 引脚定义（GPIO 2 / 13 / 34） | 照旧，硬件不用重接 |
| WiFi 名称密码（ZeroCarbonFan / 12345678） | 照旧，手机不用重新配 |
| 自动阈值 75 / 50、回差逻辑 | 照旧，原逻辑本身是对的 |
| 换算公式的 `0.6` 偏置、`166.67` 系数 | 手册 TYP 值是 **0.5** 和 **200**，但改它会让同一口空气读数**低约 17**。这跟时序改动叠在一起就分不清是谁引起的。**等时序验证过再单独调。** |

## 三、行为变化（用的人会感觉到）

1. 网页**每秒自动刷新**，不用点按钮也能看到数值变
2. 自动模式下风扇按钮是**灰的**，想手动控制要先切到「手动」
3. 网页**不存任何状态**，每次打开都是空白页再问固件要 —— 所以看到的永远是真话，不会出现「页面显示关、实际在转」
   - **同一个上电周期内**：关浏览器再开、换台手机打开，模式和风扇都还在（状态在 ESP32 的 RAM 里）
   - **断电 / 重启 / 复位后**：回到开机默认 —— **自动模式、风扇关**（RAM 掉电即失，没有写进 NVS/Flash）
4. 串口每秒打一行：`PM2.5 = 42 ug/m3   模式=自动   风扇=开` —— **验证时序改动就看这行稳不稳**

## 四、怎么验证（重要）

⚠️ **本版尚未在硬件上验证过。** 已知的验证状态：

| 项 | 状态 |
|----|------|
| HTML 渲染 | ✅ 已用无头浏览器实拍三种状态（见 `文档/web页面原型/v2页面-*.png`） |
| 网页离线可点 | ✅ 生成了离线预览 `文档/web页面原型/v2页面.html` |
| 编译 | ⏳ 见下方「编译验证」 |
| 硬件实测 | ❌ **没有** —— 手上没有板子 |

**烧录后重点看两件事**：

1. **PM2.5 读数是否稳定** —— 串口那一行连续看一两分钟。
   时序改对了应该更稳；如果反而变差，把 `PM25_SLEEP_US` 临时改回 `968` 对比一次，
   就能确定是时序的影响还是别的原因。
2. **自动/手动切换是否真的生效** —— 手动模式关掉风扇后，等 10 秒看它会不会自己开回来。
   **不回来 = 修好了**；回来了 = 还有地方漏了模式判断。

## 五、还能再改的（知道就行，这次没做）

- **换算公式标定**：把 `0.6` / `166.67` 换成手册 TYP 值 `0.5` / `200`，或实测标定 —— 等时序验证完再做
- **GPIO 2 是 strapping 引脚**：接继电器有潜在上电风险，若要换引脚，`relayPin` 改到 GPIO 25/26/27/32/33 即可，代码其余部分不用动。（⚠️ 这是 v2 当时的说法；2026-09-27 引脚已按板卡布局重排，以 `文档/接线与引脚.md` 为准。）
- **LittleFS**：等页面复杂到要拆 CSS/JS 再上（见 `文档/web页面方案.md`）
- **电量显示**：若要在网页显示光伏/电池电压，需要加分压采样电路再改代码，**涉及硬件改动**
