## 0. 怎么用这份文档

1. 先看 **第 1 节的总表**，知道自己要用的脚有没有被占。
2. 按 **第 2 节逐个设备** 接，每个设备都标了「模块侧 → ESP32 侧」和电压。
3. 接完先看 **第 3 节供电**（5V / 3.3V / 共地），再上电。

## 1. GPIO 分配总表

**10 个脚各归其主，无冲突。** 排布在 2026-09-27 按板卡引脚图重排过 ——
目标是**同一个模块的脚挨在一起**，接线不用横跨板子。

可以从上到下一条线拉过去。

### 1.2 按排针顺序看（接线照这个插）

```text

  5  GPIO34  ADC6                       34  GPIO3   RX0   ⛔ USB 串口
  6  GPIO35  ADC7  ← 光敏 AO             33  GPIO21

  8  GPIO33  ADC5  ← PM2.5 ILED         31  GPIO19

```

> **位置以图为准**：`文档/板卡/esp32_cp2102_引脚图.jpg` 中间那张带编号的图，
> 它画的是 **USB 口朝下**、左列最上面是 3V3。板子实物别凭感觉认。

**为什么排成这样**（每组都连在一起，不用跳来跳去）：

| 引脚图上是第几孔 | 这一组 | 为什么放这 |
|---|---|---|
| 6 ~ 8 | 光敏 + PM2.5（3 个脚） | ADC1 那簇（36/39/34/35/32/33）里**只有 32 和 33 能当输出**，前四个是只读脚。所以 PM2.5 的 AO+ILED 只能占 32/33，光敏只能占 34/35 —— 挨着是**没得选**，不是巧合 |
| 9 ~ 12 | 继电器四路 IN | 整块板子上**唯一连续的四个安全输出脚**。下一孔 GPIO12 是 strapping 脚，不能用 |
| 14 | GND | 紧贴继电器组，就地取地 |
| 15 | DHT11 | 就跟在 GND 下面，同一条线上 |
| 27 ~ 28（右列） | 语音 RX/TX | UART2 的原生脚，天生一对。板子左列第 16~18 孔是 Flash 脚（GPIO9/10/11），用不了 |

**还空着、随时能用**：

| GPIO | 备注 |
|---|---|
| **4** | 普通 IO，非 strapping |
| **18 / 19 / 21 / 22 / 23** | 普通 IO。默认是 SPI/I2C 功能，本工程没用 SPI，当普通脚没问题 |
| **34 / 36 / 39** | **只能输入**、无内部上下拉 —— 适合按键 / 传感器输入，**不能接继电器、LED 这类输出** |

**别用的**：

| GPIO | 为什么 |
|---|---|
| **0 / 2 / 5 / 12 / 15** | **strapping 脚** —— 上电瞬间的电平决定启动模式、Flash 电压。接错了板子起不来（GPIO12 最危险，它就在继电器组下面） |
| **6 ~ 11** | 板载 Flash，占了无法启动也无法烧录 |
| **1 / 3** | USB 串口，占了看不到串口输出 |
| **37 / 38** | ESP32-WROOM-32 **模组上根本没引出来**，板边没有这两个脚（WROVER 才有） |

> ⚠️ **GPIO16 / 17 在 WROVER 模组上接 PSRAM**，本板是 **ESP-WROOM-32**（无 PSRAM），所以这两个脚可以放心用 —— 换板子前要重新确认。
>
> ⚠️ **模拟输入只认 ADC1：32 / 33 / 34 / 35 / 36 / 39。**
> GPIO 0/2/4/12/13/14/15/25/26/27 属于 **ADC2**，而 ADC2 和 WiFi 共用硬件 ——
> **主程序一开热点，`analogRead()` 在这些脚上就失效。**
> 现在两个模拟输入（光敏→35、PM2.5→32）都在 **ADC1**，开热点也能读 ✓。
> 33 虽然也是 ADC1，但本项目只拿它做数字输出（ILED），不用它的 ADC。

## 2. 逐个设备的接线

### 2.1 ESP32 开发板

- 型号：**WAVGAT ESP-WROOM-32**，CP2102 串口芯片，Type-C。
- **USB 线既供电又能看串口** —— 但只适合单模块调试；
  继电器四路一起吸合 + 语音模块时**必须用 DC-DC 的 5V**，见第 3 节。

### 2.2 PM2.5 粉尘传感器（GP2Y1014AU + 转接板）

| 转接板脚 | 接到 | 说明 |
|---|---|---|
| **VCC** | **5V** | ⚠️ 必须 5V，3.3V 不工作 |
| **GND** | GND | |
| **AO** | **GPIO 32** | 模拟输出，板上已 ÷11 分压 |
| **ILED** | **GPIO 33** | 脉冲点亮内部红外 LED（和第 7 孔的 AO 挨着） |

- 分压已在转接板上（150Ω + 220µF + 10k/1k），**不用再加电阻**。
- 串口 `raw` 应落在 **0 ~ 450**；冲到 4000 以上 → 说明板上没分压，**立刻断电**。
- 读数用 `analogReadMilliVolts()`，不用 `analogRead()`（见 `文档/传感器/PM2.5_GP2Y1014AU.md`）。

### 2.3 光敏电阻模块（4 线制）

| 模块脚 | 接到 | 说明 |
|---|---|---|
| **VCC** | **3.3V** | ⚠️ 别接 5V（它 DO 有 10k 上拉到 VCC，5V 会灌进 GPIO） |
| **GND** | GND | |
| **AO** | **GPIO 35** | 只读输入脚，正适合做 ADC |
| **DO** | **空着不用** | 比较器输出，本项目只读模拟量 |

### 2.4 温湿度传感器（DHT11 + YL-47 模块）

| 模块脚 | 接到 | 说明 |
|---|---|---|
| **VCC** | **3.3V** | ⚠️ 别接 5V |
| **DATA** | **GPIO 13** | 模块板载 4.7k 上拉，不用外加 |
| **GND** | GND | |

- 手册要求**上电后等 1 秒**才能读；分辨力为 1（温湿度都是整数）。

### 2.5 4 路继电器模块（光耦隔离 · 低电平触发）

| 继电器脚 | 接到 | 说明 |
|---|---|---|
| **VCC** | **3.3V** | 光耦**逻辑侧**参考电压，和 ESP32 同电位 |
| **JD-VCC** | **5V** | 线圈侧供电 |
| ⚠️ **VCC↔JD-VCC 跳线帽** | **必须拔掉** | 不拔会有 1.7V 压差，光耦微导通 → 继电器抖动发热 |
| **GND** | GND | ⚠️ 必须和 ESP32 共地 |
| **IN1** | **GPIO 25** | 进/排风扇 |
| **IN2** | **GPIO 26** | 灯 |
| **IN3** | **GPIO 27** | 抽湿机 |
| **IN4** | **GPIO 14** | 空调 |

- 触点侧接 12V 负载（风扇），**12V 绝对不能进 ESP32 引脚**。
- 上电不误吸合靠 `relay.h` 的顺序：**先写锁存器（HIGH）再 `pinMode(OUTPUT)`**。

### 2.6 语音模块（CI1302 · 串口 UART1）

**协议证据**（不是猜的，都能翻到原文）：

| 事实 | 出处 |
|---|---|
| 走 **UART1**、**115200** | `user_config.h`：`UART_PROTOCOL_NUMBER = HAL_UART1_BASE`、`UART_PROTOCOL_BAUDRATE = UART_BaudRate115200` |
| 协议是 8 字节帧 `A5 FA 00 … FB` | `user_msg_deal.c` 的 `send_data[]` / `recv_data[]`，**逐字节写死** |
| 指令表就是你那份 xlsx | `文档/传感器/语音控制模块/命令词播报词协议列表V3_中文模板.xlsx` |
| 模块侧两个通信脚 = 排针 `UART1_RX` / `UART1_TX` | 厂家原理图 `ci-d0xgs02s-原理图.pdf` J1 的 7、8 脚 |
| IO 电平默认 **3.3V**（可直连 ESP32） | 厂商 `！！！重要Readme！！！_V11.pdf` 第三节第 2 条 |

**接线**：

| 语音模块脚（你报的丝印） | 接到 | 说明 |
|---|---|---|
| **5V** | **DC-DC 5V** | 这是**电源输入**（原理图标 `VDD_5V` + 「电源输入请添加大电容」），不是 3.3V 输出 |
| **GND** | **GND** | ⚠️ 必须和 ESP32 共地，不共地什么都不会通 |
| **信号脚①** | **GPIO 16** | 程序里当 **RX**（模块 → ESP32），**先只接这一根** |
| **信号脚②** | **GPIO 17** | 程序里当 **TX**（ESP32 → 模块），**等①确认了再接** |

> ⚠️ **丝印两个信号脚都叫 TX（TX1 / TX2），光看丝印分不出谁发谁收。**
> 所以**一次只接一根**，用下面的办法实测判定 —— 这样就算判反了也不会有两个
> 推挽输出直接对撞：
>
> 1. 只接 **5V、GND、信号脚①→GPIO16**，信号脚②**先空着**
> 2. 烧 `[env:voicetest]`，打开串口监视器（115200）
> 3. 对模块说 **「你好小丹」**
>    - 打出 `A5 FA 00 81 01 00 21 FB → 指令：你好小丹（唤醒词）` → **①就是发送脚**
>      → 断电，把信号脚②接上 GPIO17，接线完成
>    - 一个字都没有 → 断电，**把两根信号线对调**再试
> 4. 接完②后在控制台按 `1`~`7`，模块应该念一句话 —— 这验的是反方向那根线
>
> **如果①能收到、但接上②后模块没反应**：说明这四个脚里可能**只引出了发送、
> 没引出接收**。那就把②从 GPIO17 上断开，**只用单向收指令** ——
> 「收指令 → 开灯 / 开风扇」的主流程完全不受影响，只有「让模块主动播报」用不了。

**上电握手（先过这关，再测指令）**：

模块上电后会**反复**发一帧等我们回话 —— 2026-09-27 首次上板就刷到了：

| 方向 | 帧 | 说明 |
|---|---|---|
| 模块 → ESP32 | `A5 FA 00 80 0A 00 21 FB` | **波特率同步请求**（约每 0.4 秒一次） |
| ESP32 → 模块 | `A5 FA 00 80 0A 00 22 FB` | **ACK**（和请求只差校验那一个字节） |

- **不回 ACK**：模块一直重发；而且校准期间它会把波特率在
  115200×0.90 ~ ×1.10 之间来回试 —— **换挡那几帧收进来就是错位的字节**
  （实测出现过 `A5 FA 00 00 0A 00 61 FB`：类型字节 `0x00` 不属于任何已知类型，
  而且它出现在一个双倍间隔之后）。
- **回了 ACK**：模块锁定波特率、停止重试，才会走到发指令那一步。
- `voiceTest.cpp` 收到请求会**自动回 ACK** —— 能逐字节认出这个 8 字节帧，
  本身就证明波特率是对的，所以这个 ACK 回得放心。
- 出处：SDK `user_msg_deal.c` 里 `defined_send_baudrate_sync_req()` 发请求，
  `com_msg_process()` 里 `memcmp(p_data, "\xA5\xFA\x00\x80\x0A\x00\x22\xFB", …)`
  认 ACK；和你那份 xlsx「握手协议」的两行完全一致。

**指令对照表**（模块 → ESP32，类型 `0x81`）：

| 帧 | 指令 |
|---|---|
| `A5 FA 00 81 01 00 21 FB` | 你好小丹（唤醒词） |
| `A5 FA 00 81 02 00 22 FB` | 开灯 |
| `A5 FA 00 81 02 00 23 FB` | 开风扇 |
| `A5 FA 00 81 02 00 24 FB` | 关灯 |
| `A5 FA 00 81 03 00 25 FB` | 关闭风扇 |
| `A5 FA 00 81 0A 00 2A FB` | 欢迎语（上电） |
| `A5 FA 00 81 0B 00 2B FB` | 休息语（退出唤醒） |

> ⚠️ **第 7 字节的「校验」不是前 6 字节的累加和。**
> 开风扇 / 关灯 / 关闭风扇这三条，按字节累加算出来是 `0x22 / 0x22 / 0x23`，
> 实际发的是 `0x23 / 0x24 / 0x25`。
> 所以解析只能**整帧逐字节比对**，改成「算校验和」会认错指令。

**关于 IIC**：这块模块硬件上串口和 IIC 是**同一对芯片脚的两种固件配置**
（芯片引脚复用表：`PA2 = TX1 / IIC0_SDA`，`PA3 = RX1 / IIC0_SCL`）。
但参考固件里 `MSG_USE_I2C_EN` **默认是关的**，你这份 `…_UART1_115200_…` 固件
走的就是串口。**这次先按串口接**；以后要改 IIC，得换固件、重新选脚。

## 3. 供电与共地

```
太阳能板 ──► 太阳能控制器 ──► 12V 电池 ──┬──► 继电器触点 ──► 12V 风扇
                                        │
                                        └──► DC-DC 降压 ──► 5V ──┬──► ESP32 (5V/VIN)
                                                                  ├──► PM2.5 转接板 VCC
                                                                  ├──► 继电器 JD-VCC（线圈）
                                                                  └──► 语音模块 5V

ESP32 板载稳压器 ──► 3.3V ──┬──► 光敏模块 VCC
                            ├──► 继电器 VCC（光耦逻辑侧）
                            └──► DHT11 VCC
```

**两件事必须做到，否则整板不工作或烧件：**

1. **所有 GND 连成一片** —— 语音模块、PM2.5、光敏、DHT11、继电器、ESP32
   六个地必须通。最省事：全部接到面包板的同一条地线。
2. **5V 和 3.3V 别接串** —— 接反了轻则不工作，重则灌电流。

**电流余量（粗算，接完要实测）：**

| 负载 | 大约 | 数字哪来的 |
|---|---|---|
| 4 路继电器同时吸合 | ~280 mA | `文档/材料清单.md` 给的估算 |
| 语音模块 | 厂家原理图标 **5V/1A**，含功放推喇叭，**峰值可达数百 mA** | 原理图 Block Diagram / Power Tree 页 |
| PM2.5 转接板 | 未实测 | — |
| ESP32 开热点 | 未实测（WiFi 发射时明显比待机大） | — |

> ⚠️ **光是前两项上限相加就已经 1.28A**，再加 ESP32 和 PM2.5，
> **DC-DC 若是 1.5A 版本，余量偏紧**；优先用 **3.5A 版本**，
> 或者至少让「语音模块 + 继电器线圈」和「ESP32」分清两路 5V，
> 避免互相拖垮（一压降 ESP32 就重启）。
> **判据**：一说话、或继电器一吸合板子就重启 / 串口断 → 就是供电不够。

**布线小建议**：语音模块的麦克风线和喇叭线是小信号，尽量**离开 PM2.5 / 光敏的
模拟线**（那两根走 ADC），绕开一点，读数会稳一些。

## 4. 建议的接线顺序

1. **只接 ESP32 + USB** —— 烧 `esp32dev`，确认串口能看到日志。
2. **加 PM2.5 + 光敏 + DHT11**（三个传感器，纯读不驱动）→ 烧 `sensor_pm25` /
   `sensor_dht11` / 主程序，确认读数正常。
3. **加语音模块**（按 2.6 的两步判定法）→ 烧 `[env:voicetest]`，说话看指令。
4. **最后加继电器**（跳线帽拔掉，先不接 12V 负载）→ 烧 `[env:relaytest]`，
   听四路「咔哒」。
5. **全接齐** → 接 12V 负载 → 烧主程序整体测。

> **为什么继电器放最后**：继电器一动作就是强电/大电流，前面哪一步没验完就上
> 它，出了问题分不清是接线还是逻辑。而且继电器会随传感器数值乱响，干扰判断。

## 5. 分步测试（每步的预期现象）

| 步骤 | 烧哪个 env | 你会看到什么 | 不对怎么办 |
|---|---|---|---|

## 6. 语音已经并进主程序了（2026-09-27）

这一节原来是「怎么并」的计划，现在做完了，改成记录落地形态：

1. **`src/voice.h`** —— 和 `light.h` / `pm25.h` / `dht11.h` 一个形态：
   只有头文件、不带 setup/loop，所以 **`platformio.ini` 一行都没改**
   （`build_src_filter` 只筛 `.cpp`，管不到 `.h`）。
   三个函数：`voiceInit()`（开 `Serial2`）/ `voicePoll()`（收字节组帧）/
   `voiceTakeCmd()`（取走一条指令，取完清空）。
2. **用 `Serial2`（GPIO16/17），没动 `Serial`** —— 后者是 USB 控制台和日志。
3. **`voicePoll()` 非阻塞**，和 `dnsServer.processNextRequest()`、
   `server.handleClient()` 一起在 `loop()` 里每轮调。一帧 8 字节 @115200 ≈ 0.7ms。
   ⚠️ **握手应答在 `voicePoll()` 里自动做了**：认出
   `A5 FA 00 80 0A 00 21 FB` 就回 `A5 FA 00 80 0A 00 22 FB`。
   漏掉这一步，模块会每 0.4 秒刷一帧、还会来回试波特率。
4. **指令 → 动作**（复用 `relaySet()`，没新写驱动）：

   | 语音指令 | 动作 | 继电器 |
   |---|---|---|
   | 开灯 | `relaySet(DEV_LIGHT, true)` | IN2 · GPIO26 |
   | 关灯 | `relaySet(DEV_LIGHT, false)` | IN2 · GPIO26 |
   | 开风扇 | `relaySet(DEV_FAN, true)` | IN1 · GPIO25 |
   | 关闭风扇 | `relaySet(DEV_FAN, false)` | IN1 · GPIO25 |
   | 你好小丹 / 欢迎语 / 休息语 | 只在串口打日志，不动设备 | — |

5. **语音算「手动操作」**：执行完立刻把 `set.mode` 切成 1 并存 NVS。
   所以语音那段**必须放在自动控制之前** —— 同一次 `loop()` 走到下面时
   模式已经是手动，自动判据就跳过了。不这么做就会重演原版那个坑
   「语音刚关掉的风扇，下一轮又被自动判据开回来」（CLAUDE.md 已知的坑第 5 条）。

**已知的取舍**：`voicePending` 只留**一条**指令，不做队列 ——
连说两条挤进同一次 poll 时，后一条覆盖前一条（按「用户最后说的算」）。
实际上两条指令之间隔着零点几毫秒就被取走了，基本碰不上（`voice.h` 里有说明）。

**还没做的**：网页上没显示语音状态，目前只能在串口日志里看
（`[语音] 识别到：开风扇`）。演示要展示的话可以再加。
