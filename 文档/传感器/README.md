## 二、引脚占用总表

⚠️ **加新设备选引脚前先看这张表**，完整引脚定义见 `文档/板卡/esp32_cp2102_引脚图.jpg`。

| GPIO | 接什么 | 说明 |
|---|---|---|
| **14** | PM2.5 的 ILED | 普通数字输出 |
| **32** | PM2.5 的 AO | **ADC1**，必须 |
| **35** | 光敏模块的 AO | **ADC1**，只读输入脚 |
| 34 / 36 / 39 | 空 | 只读输入脚，可做 ADC |
| 4 / 13 / 16 / 17 / 18 / 19 / 21 / 22 / 23 / 25 / 26 / 27 / 33 | 空 | 普通 IO |

**绝对不能用的**：

| 引脚 | 为什么 |
|---|---|
| **0 / 2 / 5 / 12 / 15** | **strapping 脚** —— 上电瞬间的电平决定启动模式、Flash 电压。接继电器/传感器可能让板子起不来（其中 GPIO12 最危险） |
| **6–11** | 接着板载 Flash —— 占了无法启动、也无法烧录 |
| **1 / 3** | USB 串口（TX0/RX0）—— 占了看不到串口输出 |

> ⚠️ **模拟输入（ADC）只认 ADC1：GPIO 32 / 33 / 34 / 35 / 36 / 39**
> GPIO **0 / 2 / 4 / 12 / 13 / 14 / 15 / 25 / 26 / 27 属于 ADC2，而 ADC2 和 WiFi 共用硬件 —— 主程序一开热点，`analogRead()` 在这些脚上就失效**。
> 引脚图上标 `ADC0`~`ADC7` 的是 ADC1，标 `ADC10`~`ADC19` 的是 ADC2，一眼能分。

## 三、几条共通的坑（每个传感器都会遇到）

### 1. 供电电压别搞混，两块传感器要求相反

| 模块 | VCC 接哪 | 为什么 |
|---|---|---|
| **PM2.5 转接板** | **5V** | 手册 Vcc = 5±0.5V，3.3V 不工作 |
| **光敏模块** | **3.3V** | 它的 DO 有 10K 上拉到 VCC，接 5V 会让 5V 电平进 GPIO，而 **ESP32 的 GPIO 不是 5V 容限** |

### 2. 模拟读数**必须**用 `analogReadMilliVolts()`

**不要**用 `analogRead() * 3.3 / 4095`。

ESP32 的 `analogRead()` 在**低压段（<0.1V）分辨率极差、经常直接返回 0**。而这两个传感器的模拟输出都很小（几十~几百 mV），用 `analogRead()` 会一直读到 0，**看上去就像「传感器坏了 / 没接 / 没输出」**。

`analogReadMilliVolts()` 会读芯片出厂烧在 efuse 里的校准系数，把非线性补偿掉，低压段能正常读数。

> **我们为此白查了整整一轮** —— 见 [PM2.5_GP2Y1014AU.md](PM2.5_GP2Y1014AU.md) 的「踩过的坑」。

### 3. 传感器读一次是**阻塞**的，别放进 `sendState()`

| 传感器 | 读一次耗时 |
|---|---|
| PM2.5 | **约 10ms**（要等够 LED 的 10ms 脉冲周期） |
| 光敏 | 极快（纯 ADC 读取） |

`main.cpp` 的 `loop()` 里必须频繁调 `server.handleClient()`，**一旦被堵住网页就没响应**。

**正确做法**：在 `loop()` 里用 `millis()` 定时采（每秒/每两秒一次），把结果存进全局变量，`sendState()` 直接用缓存值。

### 4. 读数是「相对值」，不是仪器读数

两个传感器都**未经专业仪器标定**：零点按所在环境校的，灵敏度用手册标称值。
**判高低、看变化、做联动 —— 够用；当仪器读数 —— 不行。**

厂商说明书里也明确写了这条（「需配专业粉尘检测仪进行对比实验，修正转换系数」）。
