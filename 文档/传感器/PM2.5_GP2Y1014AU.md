# PM2.5 粉尘传感器 —— GP2Y1014AU + 转接板

> 代码在 `代码/ZeroCarbonFan_v2/ZeroCarbon/src/pm25.h`
> 状态：✅ **已上板验证**（2026-09-26）

## 一、接线：4 根线，转接板上已含全部元件

| 转接板 | 接到 ESP32 | 说明 |
|---|---|---|
| **VCC** | `VIN` / 5V | ⚠️ **5V，不是 3.3V**。手册 Vcc = 5±0.5V |
| **GND** | GND | 必须共地 |
| **AO** | **GPIO32** | 模拟输出。**必须是 ADC1 的脚** |
| **ILED** | **GPIO14** | 红外 LED 驱动 |

**不需要外接任何元件** —— 转接板上已经有：
- **150Ω + 100µF×2** —— 供电 RC（手册要求 V-LED 串 150Ω、并 220µF）
- **10k / 1k** —— 模拟分压
- 一颗 **电源指示灯 D1** —— 亮 = 板内 5V 正常（**排查供电时先看它**）

> ⚠️ 接线前核对板子丝印，以实物为准。

## 二、三个关键参数（每条都有来历，别乱改）

### ① `LED_ON_LEVEL = HIGH` —— 高电平点亮

转接板上 ILED 经一颗 **SS8050 三极管（NPN）**驱动：

```
ILED ──[R8 10k]──┬── Q1 基极
                 └──[R9 47k]── GND
                 Q1 集电极 ──→ K_LED（传感器 3 脚）
                 Q1 发射极 ──→ GND
```

**ILED 给高电平 → 三极管导通 → 3 脚被拉到 GND → LED 点亮。**

⚠️ **网上流传的那份 Arduino 示例写 `digitalWrite(ledPower, LOW)` 点亮** —— 那是**直连**（MCU 引脚直接灌电流）的写法。**这块转接板上有三极管，极性是反的**，照抄上去 LED 根本不亮。

**厂商的 STM32 例程写的是 `GPIO_SetBits`（高电平）= 点亮 ✓ 那份才是对的。**

### ② `DIVIDER_RESTORE = 11` —— 分压还原

```
传感器 5 脚 VO ──[R6 1k]──┬── AOUT（就是转接板的 AO）
                          └──[R10 10k]── GND
```

AO 上只有传感器真实输出的 **1/11**，必须乘 11 还原。

> **依据**：厂商 STM32 例程的注释原文 ——「转接板是1K跟10K的电阻分压采集，所以程序计算时要乘11」

### ③ `NO_DUST_MV = 1562` —— 零点，**每台都要重校**

传感器在"没有粉尘"时不是输出 0V，而是一个正的基线电压。这个基线**每枚传感器都不一样**，必须实测。

**现在用的值 1562，是在本项目所在房间实测的**（干净空气下 AO = 142mV，×11 = 1562mV）。

**重校方法**：
1. 把传感器拿到**通风处 / 户外**（越干净越好），读串口的 `Vo=`
2. 把那个数填进 `NO_DUST_MV`
3. 重烧 → 干净空气下 PM2.5 应该接近 0

> **厂商例程里的 `NO_DUST_VOLTAGE` 是 400**，但它的注释写「通常在 500-900 之间」—— **值和注释自己就打架**。而且那是在**厂商的环境**测的，对你这台、你这个房间都不适用。
>
> 它的注释里还有一句值得注意：**「遮住传感器时的电压」**。如果你把传感器完全遮住（贴黑胶布）读一次 `Vo=`，会得到一个更低的基线 —— 那是另一种定零点的方法。本项目用的是「干净空气」，因为它让日常显示接近 0，更直观。

### `COV_RATIO = 0.20` —— 换算系数（这个不用改）

`µg/m³ = (VO − 零点) × 0.20`

来自手册灵敏度 **K = 0.5V / 100µg/m³** → 5mV per µg/m³ → 乘 0.20 ✓ 标准值。

> 厂商例程的注释写「通常在 0.17 左右」但值是 `0.20f` —— **又是注释错、值对**。

## 三、读数怎么来的（**这里是最大的坑**）

### ⚠️ 必须用 `analogReadMilliVolts()`，不能用 `analogRead()`

```cpp
// ❌ 错：ESP32 的 analogRead() 在低压段恒返回 0
int raw = analogRead(PM25_AN_PIN);
voltage = raw * 3.3 / 4095;

// ✅ 对：校准读法，低压段能正常读数
int mv = analogReadMilliVolts(PM25_AN_PIN);
```

**为什么**：干净空气下 AO 只有 **约 142mV**。ESP32 的 `analogRead()` 在 **<0.1V 附近分辨率极差、经常直接返回 0**。
用它会一直读到 0，**看上去就是「传感器坏了 / 没接 / 没输出」**。

`analogReadMilliVolts()` 会读芯片出厂烧在 **efuse 里的校准系数**，把 ADC 的非线性补偿掉。这是 ESP32 专用读法。

### 采样时序（手册要求，别改）

```
LED 开 ──280µs──> 采样 ADC ──40µs──> LED 关 ──9680µs──> 下一轮
└──────────────── 320µs 脉宽 ────────────────┘
└──────────────────── 10ms 周期 ─────────────────────┘
```

依据手册「Recommended input condition for LED」：脉冲周期 **10±1ms**、脉宽 **0.32±0.02ms**、采样点 **脉冲开始后 0.28ms**。

> **原版固件在这里有个 bug**：`offTime` 写成 `968` 而不是 `9680`，少了**一位数** → 实际周期只有 1288µs，比手册快 7.8 倍，LED 占空比从 3.2% 变成 25%。既不准确也伤 LED 寿命（手册注：连续工作 5 年光衰 50%）。本项目已改正。

### 阻塞时间

`pm25Read()` **阻塞约 10ms**（必须等够脉冲周期）。
所以**只能在 `loop()` 里定时调**（本项目 1 秒一次），**不能放进 `sendState()`** —— 那会让每次网页请求都多等 10ms，页面立刻变卡。

## 四、踩过的坑（按时间顺序，都是真金白银）

这一轮排查花了很久，记下来免得重蹈。**下次遇到「读数恒为 0」，直接跳到第 3 条。**

### 1. 分压比是 **11**，不是 2

早期照着"裸传感器 + 10k/10k 分压"估成 ×2。**×2 会把电压压到 0.7V 以下，减掉零点后读数几乎恒为 0。**

### 2. LED 极性：**HIGH 点亮**

见上面参数 ①。Arduino 那份示例的 LOW 点亮是直连写法，**不适用这块转接板**。

### 3. ⭐ **`analogRead()` 在低压段恒返回 0**（最大的坑）

这是让整轮排查跑偏的根源。`raw=0` **不代表传感器没输出** —— 它只是说明读数这条路在这个电压上读不出来。

**换 `analogReadMilliVolts()` 之后，同一个引脚立刻读出 142mV，传感器一直是好的。**

### 4. 几个把水搅浑的中间现象

| 现象 | 真相 |
|---|---|
| 「瞬时值在 0↔2047 之间乱跳」 | **引脚悬空**（线没接通）。稳定的小值才是真实信号 |
| 「切换 ILED 电平，读数不变 → LED 没被驱动」 | **假警报**。开机自检是在**静止空气**下比较两档的 —— 环境没变，LED 开不开读数本来就一样。**判断 LED 好坏要用「点烟/塞头发看读数变不变」** |
| 「短接 3.3V 却只读到 1000mV 且乱跳」 | 当时 **AO 线和短接线同时插在引脚上**，两个电源在打架 |
| 「读数一直是 232 µg/m³ 不动」 | 零点没校准（用了厂商的 400）+ **环境 PM2.5 本来就没变**。塞根头发进去立刻能看到变化 |

### 5. 那张「0-75 非常好 / 1050-3000 差」的分级表**不要用**

它配的是**另一套公式** `(raw/1024 − 0.0356) × 4200`，量程 **0~4046**。

按手册灵敏度，要读到 3000 µg/m³ 传感器得输出 **15V** —— 而它最高只有约 4V。**那张表里的高档位，这个传感器物理上到不了。**

**本项目用的是国标 GB 3095-2012**（网页 `grade()` 函数）：

| 等级 | µg/m³ |
|---|---|
| 优 | 0–35 |
| 良 | 35–75 |
| 轻度污染 | 75–115 |
| 中度污染 | 115–150 |
| 重度污染 | 150–250 |
| 严重污染 | >250 |

正好覆盖本传感器 0~490 的量程 ✓
