# 语音控制模块 使用说明（CI1302 · 串口版）

> **模块**：启英泰伦 **CI1302**（硬件资料对应 CI-D02GS02S / CI-D03GS02S）
> **通信**：串口 **UART1 · 115200 · 8N1**（模块硬件上串口和 IIC 是同一对脚的两种固件配置，本固件走串口）
> **固件**：`语音芯片sdk/CI1302_chinese_1mic_V01072_UART1_115200_2M.bin`
> **代码**：主程序用 `src/voice.h`；单独调试用 `src/voiceTest.cpp`（`[env:voicetest]`）
> **接线**：`文档/接线与引脚.md` 第 2.6 节（5V / GND / 两根信号线 → GPIO16 收、GPIO17 发）
> 建立：2026-09-27

---

## 一、先记住三件事

1. **上电必须回握手帧** —— 不回，模块每 0.4 秒重发一次，还会来回试波特率，
   收到的就是错位乱码。详见第二节。
2. **第 6 个字节不是校验和，是厂商命令码** —— 解析**只能整帧逐字节比对**，
   写成「算校验和」会认错指令。
   详见第五节。
3. **模块上电一定会发握手帧** —— 收不到就说明：没接 / 没供电 / 两根信号线收发接反了。
   这是最好用的一个诊断信号。

---

## 二、上电握手（必须应答）

模块上电后会**反复**发这一帧等主机回话：

| 方向 | 帧 | 含义 |
|---|---|---|
| 模块 → ESP32 | `A5 FA 00 80 0A 00 21 FB` | 波特率同步请求 |
| ESP32 → 模块 | `A5 FA 00 80 0A 00 22 FB` | ACK（只差最后一个字节） |

**不回 ACK 会怎样**（2026-09-27 实测）：

- 模块**每 0.4 秒重发一次**
- 校准期间它会把波特率在 **115200×0.90 ~ ×1.10** 之间来回试 ——
  **换挡那几帧收进来就是错位的字节**（实测出现过 `A5 FA 00 00 0A 00 61 FB`，
  第 4 字节 `0x00` 不属于任何已知类型，而且它出现在一个双倍间隔之后）
- 回了 ACK，模块才锁定波特率、停止重试，也才走到发指令那一步

**为什么可以放心自动回**：ACK 的意思是「你这个波特率我收对了」——
而我们能把这个 8 字节帧逐字节认全，本身就证明波特率是对的。

> 代码里这个应答在 `voice.h` 的 `voicePoll()` 里自动做；单独测试程序
> `voiceTest.cpp` 也做。**并进主程序后不能省**。

## 三、控制指令（模块 → ESP32，类型 `0x81`）

| 帧 | 命令词 | 说明 |
|---|---|---|
| `A5 FA 00 81 01 00 21 FB` | **你好小丹** | 唤醒词，不控制设备 |
| `A5 FA 00 81 02 00 22 FB` | **开灯** | |
| `A5 FA 00 81 02 00 23 FB` | **打开风扇** / **开风扇** | 两个说法发的是**同一帧** |
| `A5 FA 00 81 02 00 24 FB` | **关灯** | |
| `A5 FA 00 81 03 00 25 FB` | **关闭风扇** / **关风扇** | 两个说法发的是**同一帧** |
| `A5 FA 00 81 03 00 28 FB` | **开抽湿机** | 2026-09-28 新增 |
| `A5 FA 00 81 02 00 25 FB` | **关抽湿机** | 2026-09-28 新增。命令码和「关闭风扇」相同，**正常**，见第五节 |
| `A5 FA 00 81 03 00 26 FB` | **开空调** | 2026-09-28 新增 |
| `A5 FA 00 81 03 00 27 FB` | **关空调** | 2026-09-28 新增 |
| `A5 FA 00 81 0A 00 2A FB` | **欢迎语** | 模块上电时自己发 |
| `A5 FA 00 81 0B 00 2B FB` | **休息语** | 退出唤醒状态时自己发 |

- **一个动作可以有几种说法**：固件 2026-09-27 更新后，说「开风扇」和「打开风扇」
  模块都发 `81 02 00 23`；说「关闭风扇」和「关风扇」都发 `81 03 00 25`。
  所以**代码里按帧处理就行，不用为同义说法分叉**。
- 欢迎语 / 休息语**不是命令词**，是模块自己在特定时机发的（上电 / 退出唤醒），
  收到不要当成用户操作。
- 模块识别到命令词会**自己播一句确认语**（主动播报模式），不需要主机下指令。

## 四、反向指令（ESP32 → 模块，类型 `0x82`）

把上面表格里第 4 字节的 `0x81` 换成 `0x82`，就是「让模块播这一句」的帧 ——
用途是让模块**在不识别语音的情况下也念一句**（比如网页上按了开关，让模块出声）。

| 帧 | 播哪一句 |
|---|---|
| `A5 FA 00 82 01 00 21 FB` | 你好小丹 |
| `A5 FA 00 82 02 00 22 FB` | 开灯 |
| `A5 FA 00 82 02 00 23 FB` | 打开风扇 / 开风扇 |
| `A5 FA 00 82 02 00 24 FB` | 关灯 |
| `A5 FA 00 82 03 00 25 FB` | 关闭风扇 / 关风扇 |
| `A5 FA 00 82 03 00 28 FB` | 开抽湿机（2026-09-28 新增） |
| `A5 FA 00 82 02 00 25 FB` | 关抽湿机（2026-09-28 新增） |
| `A5 FA 00 82 03 00 26 FB` | 开空调（2026-09-28 新增） |
| `A5 FA 00 82 03 00 27 FB` | 关空调（2026-09-28 新增） |
| `A5 FA 00 82 0A 00 2B FB` | 欢迎语 ⚠️ 命令码是 `2B`，不是 `2A` |
| `A5 FA 00 82 0B 00 2C FB` | 休息语 ⚠️ 命令码是 `2C`，不是 `2B` |

⚠️ **注意最后两行**：欢迎语 / 休息语在**两个方向上命令码不一样**（`2A / 2B` 与 `2B / 2C`），
别照抄错方向的那一栏。**设备指令**（开灯 … 关空调那 8 条）没这个问题 ——
收发同一帧，只有第 4 字节 `81` ↔ `82` 不同。

> 本项目**主程序目前没用到反向指令**（模块自己会播报，够用了）。
> 单独测试程序 `voiceTest.cpp` 里用到了 —— 按控制台 `1`~`9` / `0` / `-` 会发这些帧，
> 用来验证 **ESP32→模块** 那根线通不通。

## 五、帧格式

```
A5 FA 00 <类型> <命令词> 00 <命令码> FB      （固定 8 字节）
```

| 字节 | 含义 |
|---|---|
| 0–2 | 帧头 `A5 FA 00` |
| 3 | **类型**：`0x80` 握手 / `0x81` 识别结果 / `0x82` 主机要求播报 |
| 4 | **命令词**（分组号，见下面的坑） |
| 5 | 固定 `00` |
| 6 | **命令码** —— ⚠️ **不是校验和**，见下 |
| 7 | 帧尾 `FB` |

### ⚠️ 第 6 个字节不是校验和，是厂商命令码

**它推不出算法，所以别去算。** 证据（2026-09-28 查 SDK 源码）：

- 串口这条路（`user_msg_deal.c`）里帧**全是一串写死的字符串**：

  ```c
  {13,"\xA5\xFA\x00\x81\x02\x00\x25\xFB",8,1},  //关抽湿机
  ```

  从头到尾**没有一行算校验和的代码**。
- 整个 SDK 里 `crc16` 只出现在**蓝牙那套**（`app_ble/rf_msg_deal.c`），
  跟串口协议没关系 —— 别翻到那里被带偏。
- 它和结构体里的 `cmd_id` 也对不上：关抽湿机 `cmd_id = 13`，第 6 字节却是 `25`。

看上去像「`0x20 + 序号`」，但**这个规律是断的**：

| 命令词 | 第 4 字节 | 第 6 字节 |
|---|---|---|
| 你好小丹 | `01` | `21` |
| 开灯 | `02` | `22` |
| 打开风扇 / 开风扇 | `02` | `23` |
| 关灯 | `02` | `24` |
| 关闭风扇 / 关风扇 | `03` | `25` |
| **关抽湿机** | `02` | **`25`** ← 和上面撞了 |
| 开空调 | `03` | `26` |
| 关空调 | `03` | `27` |
| 开抽湿机 | `03` | `28` |
| 欢迎语 | `0A` | `2A` |
| 休息语 | `0B` | `2B` |

> **「关抽湿机」和「关闭风扇」撞了同一个命令码 —— 不是厂商笔误。**
> SDK 的 `send_data[]` / `recv_data[]` 里两条都写死成 `81 02 00 25`，
> 真机发的就是这个。**照抄即可，别自作聪明改成 `29`。**

**为什么只能整帧逐字节比对**：第 6 字节**从帧里推不出来** ——
打开风扇第 4 字节是 `0x02`、第 6 字节是 `0x23`；关抽湿机第 4 字节也是 `0x02`、
第 6 字节却是 `0x25`。同样的第 4 字节配出不同的第 6 字节，**没有规律可循**。

所以代码里就是一张 8 字节的表 + `memcmp`。**别改成「算校验和」**，会认错指令。

> 顺带记住：欢迎语 / 休息语**两个方向的命令码不同**（收 `2A / 2B`，发 `2B / 2C`）；
> 握手 / ACK 是 `21` / `22`。

## 六、踩过的坑

1. **丝印两个信号脚都叫 TX（TX1 / TX2），分不出收发** ——
   判定办法是一次只接一根，见 `文档/接线与引脚.md` 2.6。
2. **不回握手会刷屏 + 收到错位字节** —— 见第二节。
3. **组帧时别丢掉孤立的 `A5`** —— 串口按字节到，一次读取很可能**只读到帧头第一个字节**。
   如果「找不到 `A5 FA` 就清空缓冲」，那个 `A5` 会被当噪声丢掉，**整帧永久丢失**。
   正确做法：缓冲末尾若是 `A5` 就留 1 字节等后面的 `FA`。
   （2026-09-27 自测时踩到，`voice.h` 和 `voiceTest.cpp` 都已修）
4. **厂商给的 ESP32 例程引脚在本板上不能用，已删**（2026-09-27）——
   它 UART 用 GPIO35/36（**只输入，发不出去**）、IIC 用 GPIO37/38（**WROOM-32 不引出**）。
   本项目改用 UART2：GPIO16 收 / GPIO17 发。
5. **串口和 IIC 是同一对脚的两种固件配置** ——
   芯片引脚复用表写着 `PA2 = TX1 / IIC0_SDA`、`PA3 = RX1 / IIC0_SCL`，
   所以「两种接口」不是两组独立的线。参考固件里 `MSG_USE_I2C_EN` 默认是关的，
   要改 IIC 得换固件、重新选脚。
6. **供电别从 3.3V 取** —— 原理图标「供参考电源功率 5V/1A」，模块带功放推喇叭，
   峰值电流不小。
7. **别把第 6 字节叫「校验」**（2026-09-28 修正）—— 它不是校验和，是**厂商命令码**，
   **推不出算法**（SDK 的串口这条路里压根没有算校验和的代码）。
   早先这份说明写成「校验 = `0x20 + 序号`」，被「关抽湿机」的 `25` 直接推翻。
   现在统一叫「命令码」，详见第五节 —— **改代码时别再想「要不要验一下校验和」**。
